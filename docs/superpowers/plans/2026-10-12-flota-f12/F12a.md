## 1. Scop

Din poza bonului de combustibil, deja urcată prin F6 (`fuel_entries.fisier_bon_path`),
un model de viziune accesat prin OpenRouter extrage: **data și ora, litrii, valoarea
carburantului, stația, numărul bonului și CUI-ul emitentului (stația)**. Cu ele
**pre-completează** formularul de alimentare. Omul vede ce s-a completat, corectează
și apasă „Adaugă alimentarea”. **Nimic nu se salvează automat:** acțiunea de citire nu
scrie niciun rând în bază (scrie doar auditul ei).

La salvare, propunerea citită se păstrează lângă alimentare. O scrie DOAR serverul, în
context de serviciu, iar baza refuză orice altă scriere a coloanei (D12, D13). Așa,
cine aprobă foaia vede „Diferă de bon: 45,32 L citiți, 54,32 L declarați”.

## 2. De ce

- Planul (F12, „La cerere”) are pe listă „OCR pe bon (asistentul AI există)”. Pe
  12 oct, utilizatorul a cerut toate cele opt extensii F12.
- Alimentarea se completează azi de mână, pe telefon, din șase câmpuri. Pe
  telefonul șoferului, poza bonului există oricum, din F6.
- Diferența dintre ce scrie pe bon și ce s-a declarat e un semnal de control pe care
  nicio altă verificare din modul nu-l dă. Anomaliile de kilometraj prind km, nu litri.
- CUI-ul stației e, pe moment, doar informativ. Îl vor folosi exportul contabil
  (F12 „export Saga/WinMentor”: furnizorul se identifică după CUI) și importul de la
  cardurile de combustibil (deduplicarea).

**Volumul real e mic** (memoria „Volume reale mici”: 2 alimentări în 2 firme la data
planului). Câștigul se vede abia la clienți noi. Costul unei citiri e de ordinul a
0,003 USD (§4), deci nu e el argumentul împotrivă.

Se scrie după scheletul `0013_attendance.sql`: secțiuni numerotate, `begin;`/`commit;`,
`search_path = ''`, coada REVOKE/GRANT. Toate mesajele noi se scriu cu ș/ț cu virgulă.
**Nu se atinge** `internal.alimentari_inainte` (forma ultimă e la `0018_fix_flota.sql:545`;
F4 o poate rescrie, iar o copie de aici i-ar pierde reparațiile), nici politicile RLS de pe
`fuel_entries`: coloanele noi intră sub politicile și granturile existente pe tabel
(`0012:1084`, grant la nivel de tabel). **Tocmai pentru că grantul e pe tot tabelul**,
garda lui `ocr_propunere` stă în trigger, nu în aplicație (D12).

```sql
-- supabase/migrations/0210_flota_bon_ocr.sql
--
-- FLOTA, F12a: CE A CITIT AI-UL DE PE BON, LÂNGĂ ALIMENTARE.
--
-- ── CE ADUCE ────────────────────────────────────────────────────────────────
--  · fuel_entries.cui_statie — CUI-ul emitentului bonului, doar cifre (fără RO).
--    Cifra de control o verifică aplicația (src/domain/organization/cui.ts);
--    baza ține doar forma.
--  · fuel_entries.ocr_propunere — propunerea citită de pe poză. O scrie DOAR
--    contextul de serviciu (adaugaAlimentare, prin clientul admin, după ce
--    INSERT-ul omului a trecut de RLS), o singură dată, de la null la valoare.
--    Apoi e imuabilă. Motivul: grantul de insert/update e pe tot tabelul
--    (0012:1084), deci fără gardă oricine ar putea scrie o propunere inventată
--    direct prin PostgREST, iar semnalul „diferă de bon" n-ar mai valora nimic.
--
-- ── CE NU ATINGE ────────────────────────────────────────────────────────────
--  · internal.alimentari_inainte (forma ultimă: 0018:545): trigger SEPARAT.
--  · politicile alimentari_* și granturile: coloanele noi intră sub ele.
--  · niciun index nou: avertismentul de bon dublat caută pe
--    fuel_org_data_idx (organization_id, alimentat_la), 0012:272.
--
-- Proba: tests/rls/proba-flota-bon-ocr.sql. Forward-only.

begin;

-- ============================================================
-- 1. Coloane
-- ============================================================
alter table public.fuel_entries
  add column if not exists cui_statie text,
  add column if not exists ocr_propunere jsonb;

alter table public.fuel_entries
  add constraint fuel_cui_statie_ck
    check (cui_statie is null or cui_statie ~ '^[0-9]{2,10}$'),
  add constraint fuel_ocr_propunere_ck
    check (
      ocr_propunere is null
      or (jsonb_typeof(ocr_propunere) = 'object'
          and ocr_propunere ? 'v'
          and pg_column_size(ocr_propunere) <= 4096)
    );

comment on column public.fuel_entries.cui_statie is
  'CUI-ul emitentului bonului (stația), doar cifre, fără prefixul RO (0210).';
comment on column public.fuel_entries.ocr_propunere is
  'Ce a citit modelul de viziune de pe poza bonului (0210). Scrisă doar din contextul de serviciu, o dată; apoi imuabilă.';

-- ============================================================
-- 2. Propunerea o scrie doar serverul, o singură dată
-- ============================================================
-- SECURITY DEFINER ca restul triggerelor flotei; app.is_service_context()
-- citește GUC-ul `role`, nu current_user, deci merge corect și de aici
-- (comentariul din 0002_authz.sql:300-309).
create or replace function internal.alimentari_ocr_garda()
returns trigger language plpgsql security definer set search_path = '' as $$
begin
  if tg_op = 'INSERT' then
    if new.ocr_propunere is not null and not app.is_service_context() then
      raise exception using errcode = 'P0001',
        message = 'Propunerea citită de pe bon o scrie doar aplicația, la salvarea alimentării.';
    end if;
  elsif new.ocr_propunere is distinct from old.ocr_propunere then
    if old.ocr_propunere is not null or not app.is_service_context() then
      raise exception using errcode = 'P0001',
        message = 'Propunerea citită de pe bon nu se mai poate modifica după salvarea alimentării.';
    end if;
  end if;
  return new;
end;
$$;

revoke all on function internal.alimentari_ocr_garda() from public, anon, authenticated;

-- Numele sortează DUPĂ `alimentari_inainte` (triggerele cu același moment și
-- eveniment rulează în ordinea alfabetică a numelui), deci garda de foaie
-- răspunde prima.
create trigger alimentari_ocr_garda before insert or update on public.fuel_entries
  for each row execute function internal.alimentari_ocr_garda();

commit;
```

Note pentru cine o scrie:
- **Fără backfill**: coloanele sunt `null` pe rândurile existente, adică „fără OCR”, iar asta e adevărat.
- **Funcția trigger** e `security definer`, ca toate triggerele flotei (`alimentari_inainte`
  e și ea), ca apelul la `app.is_service_context()` să nu depindă de granturile lui
  `authenticated` pe schema `app`. Verifică forma cu
  `node .claude/skills/administrativo/scripts/capcana.mjs --tabela fuel_entries` și cu
  skill-ul `administrativo-migrare` (coada REVOKE/GRANT pe care o cere scheletul).
- **Contextul de serviciu** (seed, importul F12b) poate scrie `ocr_propunere` la INSERT;
  sesiunea omului, nu.
- **Ștergerea logică** (`deleted_at`, din F4 `stergeAlimentare`) e un UPDATE, dar nu
  schimbă `ocr_propunere`, deci trece.
- **Mărimea**: `fuel_ocr_propunere_ck` taie la 4096 de octeți. Propunerea are cel mult
  ~1,5 KB (câmpuri plafonate, `cale` ≤ 512, avertismente ≤ 8 × ≤ 200 de caractere), dar
  §8.4 o verifică explicit înainte de semnare, fiindcă un 23514 aici ar pica tot UPDATE-ul
  de serviciu.
- După aplicarea pe bancul local: regenerarea `src/types/database.ts` din bancul LOCAL
  (memoria „Regenerarea tipurilor”, cu cele două patch-uri manuale).
- **Coliziune**: dacă F12b sau F12g a creat deja `cui_statie` (grep în migrări), `add column
  if not exists` trece, dar `add constraint` ar pica la nume duplicat. Atunci se scoate
  constrângerea de aici, după ce se verifică că a lor e identică.

  Refuză orice altceva.
- **`parseazaDataOraBon(data, ora): string | null`**. Acceptă `DD.MM.YYYY`, `DD-MM-YYYY`,
  `DD/MM/YYYY`, `YYYY-MM-DD`; anul în [2000, anul curent + 1]; o dată care există în
  calendar. Întoarce `"YYYY-MM-DDTHH:MM"` (forma câmpului `datetime-local`, deja în ora
  României; `dataOraRomania` din `src/schemas/comun.ts:264` o convertește la salvare).
  Fără oră ⇒ `null` (nu se inventează 00:00).
- **`interpreteazaBon(raspuns, context): RezultatInterpretare`**.
  - `context`: `{ plecareCamp: string; sosireCamp: string | null; ziFoii: string | null; cuiFirma: string | null }`.
  - Întoarce `{ propunere: PropunereBon | null; avertismente: readonly string[]; motivGol: string | null }`.
  - `PropunereBon = { alimentat_la, litri, cost, statie, numar_bon, cui_statie }`, toate nullable.

  Reguli:
  - `lizibil === false` sau niciun câmp util ⇒ `propunere: null` și `motivGol`, în cuvinte:
    „Fotografia e neclară…”, „Nu pare un bon fiscal…”, „Bonul nu conține carburant…”.
  - `litri`/`cost` = suma liniilor `carburant`. Mai mult de o linie ⇒ avertisment. `adblue`
    ⇒ exclus, cu avertisment. `total` > valoarea carburantului + 0,01 ⇒ avertisment „Bonul
    are și alte produse (X lei); s-a completat doar carburantul”.
  - `litri` în afara (0; 2000] ⇒ `null` + avertisment (aceeași limită ca `alimentareSchema`).
  - `cui_statie`: `validateazaCui` din `src/domain/organization/cui.ts`. Invalid ⇒ `null`
    + „CUI-ul citit nu trece verificarea cifrei de control; verificați-l pe bon.”
  - preț pe litru în afara [4; 12] ⇒ avertisment (M6), constantă `PRET_LITRU_PLAUZIBIL` cu ⚠ în comentariu.
  - `alimentat_la` în afara [`plecareCamp`, `sosireCamp`] sau ≠ `ziFoii` ⇒ avertisment
    (baza refuză oricum cu P0001 la salvare; aici se spune mai devreme).
  - `cif_cumparator` prezent, valid și ≠ `cuiFirma` ⇒ avertisment „Bonul e emis pe alt CIF
    decât al firmei”. **Absent ⇒ nimic** (D9).
  - `statie` ⇒ trim, max 120; `numar_bon` ⇒ trim, max 60.
- **`diferenteFataDeBon(alimentare, propunere): readonly Diferenta[]`**. Compară
  litri/cost (toleranță 0,01), dată (aceeași zi și oră), CUI și numărul bonului. O
  folosește UI-ul aprobatorului.
- **`esteJpeg(octeti: Uint8Array): boolean`** (`FF D8 FF`) și
  **`faraMetadateJpeg(octeti: Uint8Array): Uint8Array`**. Parcurge segmentele până la SOS
  (`FF DA`) și omite APP1 (`FF E1`: Exif și XMP), APP13 (`FF ED`: IPTC) și COM (`FF FE`);
  păstrează APP0 (JFIF), APP2 (ICC), APP14 (Adobe) și restul (D7). Pe un JPEG malformat
  aruncă `BonNecitibil`.
